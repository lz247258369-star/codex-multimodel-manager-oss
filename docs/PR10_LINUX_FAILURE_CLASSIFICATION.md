## 分类规则与结果

- **Windows-only 平台/测试依赖：20 项**。19 项的堆栈直接落在 `ObservabilityOptions.Create` 第 46 行；测试传入 `C:\RouterOwned\logs` 或 `C:\lr14p-e2e\logs`，在 Linux `Path.IsPathRooted` 返回 false。第 20 项是测试 Fake 按 `directory + "\\"` 枚举，而生产 `Path.Combine` 在 Linux 生成 `/`，导致 70 项没有被 Fake 枚举/裁剪。不是泛称所有失败为平台问题。
- **原因不明：9 项**。日志仅暴露 HTTP `internal_error` 或它造成的 winner 断言失败，没有内部异常堆栈。配置变更的 `ConfigMutationGate.Acquire` 调用 `WaitHandle.WaitAny` 是一个有证据的候选原因（另有 Core 测试直接记录 PlatformNotSupported），但这不足以认定九项每一项的真实根因。
- **环境/工具链问题、已知历史问题、真实跨平台回归：目前未确认有项属于这三类**。MiMo 程序集实际 107 PASS / 0 FAIL，不能将这些失败归入历史 MiMo idle-timeout 偶发问题。
- 不修改平台语义、不放宽断言、不跳过 Windows 测试。完整 Windows Development Gate 仍必须执行。
